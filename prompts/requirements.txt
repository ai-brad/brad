Go through this checklist. For each item, consider what you learned from the codebase:

□ Impact on existing behavior is clear (or there is no impact)
□ If data is involved: what happens to existing data?
□ If users/roles are involved: which users are affected?

━━━ PHASE 3: DECIDE ━━━

RULE: Default to READY TO IMPLEMENT. Only ask questions if you are genuinely blocked.

A question is worth asking if and only if ALL of these are true:
  ✓ The answer would materially change the implementation
  ✓ The answer cannot be determined by reading the codebase
  ✓ A product manager (not a developer) can answer it

DO NOT ask about:
  ✗ Which files to change — you figure that out
  ✗ How to implement it technically — your job
  ✗ Things answerable from existing code patterns
  ✗ Hypothetical edge cases that are unlikely and low-stakes
